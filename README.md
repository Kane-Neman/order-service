# Order Service

An AWS order API built with Python, AWS Lambda, API Gateway, DynamoDB, EventBridge, and SNS. Serverless Framework deploys the service to the `eu-north-1` region.

## What it does

- Creates orders and stores them in the DynamoDB `orders` table.
- Retrieves orders for a customer.
- Cancels an order.
- Publishes `OrderPlaced` and `OrderCancelled` events to the default EventBridge bus. A Lambda function consumes these events and publishes notifications to SNS.
- Protects the HTTP endpoints with an API key sent in the `x-api-key` header.

## API

Use the API Gateway base URL printed by `serverless deploy`. All endpoints require the `x-api-key` header.

### Create an order

`POST /orders`

```bash
curl -X POST "$API_URL/orders" \
  -H "Content-Type: application/json" \
  -H "x-api-key: $API_KEY" \
  -d '{
    "customerId": "CUSTOMER#1234",
    "book": "Example book",
    "author": "Example author",
    "price": 10.99
  }'
```

The `customerId` is stored as supplied, so include the `CUSTOMER#` prefix in the request body. The order ID is generated by the service; the create response currently does not include it.

### Get a customer's orders

`GET /orders/{customerId}`

```bash
curl "$API_URL/orders/1234" \
  -H "x-api-key: $API_KEY"
```

The endpoint adds `CUSTOMER#` to the path parameter before querying DynamoDB. Pass the customer ID without the prefix.

### Cancel an order

`PATCH /orders/{customerId}/{orderId}`

```bash
curl -X PATCH "$API_URL/orders/CUSTOMER%231234/ORDER%235678" \
  -H "x-api-key: $API_KEY"
```

For cancellation, `customerId` must match the value stored in DynamoDB, including `CUSTOMER#`. URL-encode the `#` character as `%23`. Replace the example order ID with the actual ID.

## Configure and deploy

Requirements:

- An AWS account and credentials configured for the AWS CLI.
- Node.js and Serverless Framework v4.
- An SNS topic and an AWS Lambda execution role.

For local deployment, copy the example and replace its placeholder values:

```bash
cp .env.example .env
```

`.env` is ignored by Git; `.env.example` contains placeholders and is safe to commit. `VALID_API_KEYS` may contain multiple comma-separated keys. Never commit real credentials or put them in this README. For CI/CD, use your CI provider's secret store.

The configured Lambda role must allow the functions to access the `orders` DynamoDB table, publish to the default EventBridge bus, and publish to the configured SNS topic.

Deploy with:

```bash
serverless deploy
```

The service creates the DynamoDB table and Lambda/API Gateway resources. The table has a retain deletion policy, so removing the service does not automatically delete the table or its data.

## Configuration

The service configuration is in [`serverless.yml`](./serverless.yml). It uses the `python3.14` runtime and `arm64` architecture.

| Variable | Purpose |
| --- | --- |
| `SERVERLESS_ORG` | Serverless Framework organization |
| `AWS_LAMBDA_ROLE_ARN` | IAM role ARN used by the Lambda functions |
| `SNS_TOPIC_ARN` | SNS topic receiving order notifications |
| `VALID_API_KEYS` | Comma-separated API keys accepted by the request authorizer |
